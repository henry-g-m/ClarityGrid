Cross-cutting concern · Observability
TracesEvery HTTP request becomes a span, end-to-end, via OpenTelemetry’s FastAPI instrumentation.
DependenciesEvery Postgres query is attributed to the request that triggered it, via psycopg instrumentation.
LogsStructured, stamped with trace/span IDs, shipped to Application Insights.
MetricsA meter is wired (get_meter()) and Azure Monitor’s defaults flow through — no custom counters yet.
SYSTEM ARCHITECTURE

Two independently deployable services, not a monolith.

The backend ships as a Docker container to Azure Container Apps; the frontend is a separate static build — each deploys on its own.

Same pipeline on every merge to main — provisioning and deployment are not manual steps.
FEATURES & CAPABILITIES

What the engine underneath actually does.

Ported from the original calc logic, then extended and covered with tests.

01

Dual API surface

/ecservice/* mirrors ClarityGrid’s real endpoints and payload shapes — a genuine mock other tooling could point at. /api/* is a clean layer purpose-built for this UI.

02

Bill calculation engine

Standard, time-of-use, and demand tariffs, plus index-pricing and feed-in-credit rate bases — the same math the real API exposes.

03

What-if analysis

Switch tariffs, move to fixed-rate pricing, add battery storage, or compare costs across any two locations — against the same usage profile.

04

Battery peak-shaving simulator

State-of-charge modeling with round-trip losses — validated to lower demand charges without ever increasing a day’s peak usage.

05

Wholesale nodal pricing

Hourly day-ahead price series per ISO feed the retail-vs-wholesale comparison shown for every location.

06

Automated test coverage

pytest suite covers the calc engine, the battery simulator, tariff rate bases, and every API route.

All six are shipped in the current prototype — none are roadmap items.
